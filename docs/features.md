# Pocket Bots 功能

pocket-bots 有哪些功能。每个功能怎么用见[使用指南](USAGE.md)，怎么实现的见[设计](design.md)。

## Agent

六个编码 agent CLI 都能当 bot 的「大脑」，每个用它**自己已经登录的账号和订阅额度**，pocket-bots 不保存、不注入任何 API key。

| | Claude Code | Codex | DeepSeek Harness | OpenCode | Pi | Grok Build |
|---|---|---|---|---|---|
| 聊天、工具调用、审批卡片 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 忙时插话进正在跑的一轮 | ✅ | ✅ | —（排队） | ✅ | ✅ | ✅ |
| Stop（打断） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 重启后续接原来的会话 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| pocket-bots 的工具（ask_bot、群聊、提议…） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 你的 MCP 服务器 | ✅ | ✅ | ✅ | ✅ | ✅（Pi ≥ 1.0） | ✅ |
| 模型直接看图片 | ✅ | ✅ | — | — | ✅ | — |
| 斜杠命令（`/compact`、自定义命令、技能） | ✅ | ✅ | — | ✅ | ✅ | ✅ |
| 在群里开子 agent 并行干活 | ✅ | ✅ | ✅ | ✅ | — | ✅ |
| 向你提问（群里显示成表单） | ✅ | —（只在 plan 模式下有，pocket-bots 不用） | — | ✅ | — | ✅ |

- 左上角显示哪些 agent 就绪；没装、没登录的写明原因。
- 每个 agent 的审批模式照原样可选（比如 Claude 的 Plan / Always Ask / Accept Edits / Auto / Bypass）。

## Bot

- **新建**：空白 bot、角色模板（Assistant、Inbox、Scout、Watch、Ops，以及 EGM 用的 Elephant、Goldfish），或你存的预设；也可以导入 bot 文件。有的模板还带着它要用的技能和设置：技能随 pocket-bots 发布，建 bot 时放进技能库并算已审阅；Goldfish 有 Codex 或 DeepSeek Harness 就优先用它们，并设成只读模式。
- **开场示例（Starters）**：新聊天的开场页显示几条「可以这样问」，点一下把文字填进输入框（不发送），补完再发；不进 prompt。在 Identity 页签增删改，最多 6 条；Elephant 模板自带。
- **身份**：名字、角色、简介、头像（像素头像、上传图片、图片 URL，或填 OpenAI key 后按描述画）、朗读用的声音。
- **灵魂**：常驻指令；Playbooks（带触发词的流程指引，第一条消息里出现触发词才进 prompt）；预览新聊天会收到的完整 system prompt。所有 bot 的 prompt 里都有一句固定的话：开始工作前先读工作目录里的 `AGENTS.md`（有的话）。
- **模型**：agent、模型、思考强度、审批模式；能否联系其他 bot（Ask first / Allowed / Off）。
- **工作目录**：托管目录（`~/.pocket-bots/Bots/<id>/`），或指向你的某个项目；记忆和技能目录照样免审批读写（Claude 和 Codex 如此，Codex 是在 Auto 模式下；其他 CLI 读写它们仍可能弹审批）。单个聊天和团队的 session 可以有自己的目录，不跟 bot 走（见下面）。
- **Set up with the bot**：开一个引导聊天，bot 一次问一个问题，然后提议它自己的常驻指令和一份 `MEMORY.md` 草稿。
- **历史**：每次改设置留快照（最近 20 次），随时恢复。

## 聊天

- 每个 bot 可以有很多互相独立的聊天；第一条消息自动成为标题。
- **聊天的目录**：新聊天输入框里的 📁 选这个聊天在哪个目录干活（比如某个仓库），默认是 bot 的工作目录；按 bot 记住上次选的。主目录在聊天开始后就定了。
- **额外的文件夹**：除了主目录，聊天还可以再加几个文件夹（最多 20 个，比如同时改两个仓库）。新聊天的输入框里点 📁 旁边的 **+**，已开的聊天也一样，随时可以加、可以点 × 去掉；不用开新聊天，会话接着原来的往下走，下一条消息起 agent 就能用到新的列表（正在跑的一轮不被打断，跑完再生效）。Claude 把这些文件夹原生加进它能访问的目录；Codex 把它们加进沙箱的可写目录（Auto、Always Ask 模式），改列表时连会话都不用重开，下一轮就用新的；OpenCode、Pi、Grok、DeepSeek Harness 没有原生支持，agent 靠绝对路径访问，system prompt 里会列出这些目录，操作可能弹审批，界面上有一行提示。额外文件夹不会自动加进信任的文件夹：Claude 上和主目录一样，读文件不问，改文件按审批模式来（默认会问）；Codex 上也和主目录一样（Auto 模式下读写都不问）；其他 CLI 读文件一般不问，改文件、跑命令可能会问。审批卡 **Allow in folder…** 的候选里，请求落在哪个额外文件夹里，就把它排在前面。
- **忙时发消息**：插话（默认）、打断，或排队；⌘↵ 做另一种。排队的消息由后端发送，关掉网页也照发，可以编辑、立即发送、删除。
- **Stop / Esc**：结束当前这一轮；在等审批时先拒绝那个请求。被你停下的不算失败。
- **附件**：上传、拖入、粘贴图片和文件，或把大段文字作为附件；图片给能看图的模型看（见上表），文本附在消息里，其他文件存进 bot 目录给路径。
- **斜杠命令**：`/learn`（把刚才的做法整理成技能），加上 agent 自带的命令和技能。
- **Reply**：引用 bot 回复里的某一段再回复，bot 知道你指的是哪个。
- **⌘F**：在聊天的全部历史里查找，逐个跳转。
- 工具调用可展开看输入输出（命令和输出、文件的 diff）；计时、每轮耗时；上下文占用圆环；复制、朗读回复。
- 草稿按聊天保存在浏览器里；聊天菜单：置顶、排序、复制 id 和路径、导出对话记录（Markdown）、归档。

## 审批

- 所有 agent 的审批都由 pocket-bots 回答：bot 自己的工具免审批；其余在聊天里弹卡片（Deny / Accept），侧栏显示黄点。
- **命令白名单**：卡片上点 Always allow，同一个命令在同一个目录以后自动通过（必须完全一致）；只存在本机，不导出。
- **信任的目录**：卡片上点 Allow in folder… 选一个目录，之后这个 bot 在里面跑命令、读写改搜文件都不再问（命令写了目录外的路径照样问），等着的同类审批一起放行；也能在 Access 里直接加。只存在本机，不导出。
- **免审批的 MCP 工具**：在 Access 里逐个勾选，六个 agent 都生效。

## 记忆

- **Memory writing 开关**（Memory 页签顶部，每个 bot 一个，默认关闭；老 bot 升级后、导入的 bot 也是关闭）：打开时 bot 自己写记忆；关闭时 bot 只能读记忆（注入、Recent work、`search_chats` 照常），你仍可查看、编辑、撤销，bot 对 `MEMORY.md` 和主题文件的改动在这一轮结束时被恢复。每日日志是 pocket-bots 自己的记录，不受开关影响。
- `MEMORY.md`：长期记忆，每个新聊天都注入前 200 行（最多 24 KB）；开关打开时 bot 自己写，你也可以在 Memory 页签直接编辑。
- 主题记忆 `memory/<topic>.md`：bot 需要时自己读。
- **每日日志**：每轮结束 pocket-bots 自动记一行（不受 Memory writing 开关影响）；最近两天的作为 Recent work 进新聊天的 prompt；bot 用 `search_chats` 翻。
- **Recent work 开关**（Memory 页签，每个 bot 一个，默认打开）：关掉后新聊天的 prompt 里不再有 Recent work，适合每次都该只看你给它的东西的 bot，比如审阅文档的 bot（重审时不会先看到自己上次的结论）。只影响之后新开的聊天；每日日志照常记，`search_chats` 照常能翻；导出的 bot 带着这个设置。
- **改动记录**：记忆文件的每次改动（bot 改的、你改的、开关关闭时被恢复的）都记下，可以一键撤销，恢复也能撤销。

## 技能和 MCP

- **技能库**：新建；从 GitHub 导入（`owner/repo/path`、文件夹链接、`SKILL.md` 链接）；`/learn` 让 bot 把做法整理成技能。导入或在磁盘上被改过的技能要你审阅后才生效。每个 bot 勾选自己用的技能。
- **随 pocket-bots 发布的技能**：现在有 EGM 的 `egm`、`egm-goldfish` 两个。用带它们的模板建 bot 时才放进技能库，直接算已审阅；你没改过的，应用更新后跟着更新，改过的保留你的版本。
- **MCP 库**：stdio 命令、HTTP、SSE；从 Claude Code、Claude Desktop、Cursor 的配置或 `.mcp.json` 导入；测试连通（列出工具）后才打开；环境变量和请求头导出时隐去。每个 bot 勾选自己用的服务器和免审批的工具。

## 定时任务（Routines）

- 按计划运行：每周几天的几点、每隔 N 分钟、cron、某个时间点一次；或者收到 webhook 时运行。
- 每次运行开一个新聊天；结果卡片（Done / Failed / Missed / Skipped）可以贴到 bot 的某个聊天里。
- bot 可以用 `propose_routine` 提议，你在卡片上确认后创建。
- At a glance：未来 7 天的计划和最近的运行；Run now。
- 上一次没结束时跳过；停机期间错过的 12 小时内补跑一次。
- webhook：只监听本机，请求体作为不可信数据交给 bot；每分钟 10 次、同时 3 次、256 KB 的限制；可以换新密钥。

## 团队

- **团队**：2–6 个 bot，其中一个必须是 leader。可以给团队写一段**团队说明**（比如「改完要跑 npm test」「交付时写清改了哪些文件」），团队里每个 bot 在每个 session 里都带上；还可以设工作目录和额外文件夹。改团队只影响之后开的 session，已经开的 session 保持开始时的样子。
- **Session**：给团队发一个任务就开一个 session（一个群聊），名字取自任务；session 列在团队下面，和 bot 的聊天一样一直保留，可以在里面追问、返工，也可以改名、删除。开 session 时可以只为这一次换工作目录；同一个目录里还有别的 session 在跑时会提示。
- 每个 bot 在 session 里有自己的座位（一个普通聊天，用它自己的模型、审批、技能和工具）；它只通过群聊工具说话，审批和私事留在座位里，session 里显示「X needs your approval」。leader 一个座位；成员每件活一个座位，一次在一个座位里做，回到哪件活就接着那件活的会话。
- **工作目录**：session 的所有座位都在团队的工作目录里干活（比如大家一起改的仓库）；不设就各用 bot 自己的。session 窗口标题下面一行可以直接加减额外文件夹，每个座位都能用；座位不换新、不带简报，下一轮用新列表。
- **Leader 分工**：leader 计划、带着完整的说明派活、检查结果；别的 bot 只做派给自己的活，做完向 leader 汇报。新活是一条新的 @ 消息，成员开一个新会话做；老活的迭代在那条消息的线程里，线程就是上下文，回到老活就回到它的会话。同一个成员的几件活各有会话，一件一件做。成员的座位只带它干活用得到的规则和工具，每次请求带的固定内容少得多。请求做完后 leader 回复你的请求告诉你结果；成员一轮失败时 leader 会收到提醒。适合按模型分工省额度。
- **成员之间直接找**：发在哪里，对方就在哪里的上下文里处理。默认在顶层发一条写清楚的请求 @ 它：它开新会话做，答案回到发请求的那个会话，请求上标着「for #N」。要对方了解这件活，就在这件活的线程里 @ 它：它为这个线程开一个会话，带上线程内容，不打断手上的活。问的是对方手上那件活、又知道它的编号（派活说明里写了），就到那件活的线程里 @ 它：它在做那件活的会话里回答。成员汇报时写清从谁那里拿到了什么；这件活的线程里有一行行链接，指向成员从这里去问过的地方。只叫醒被找的那个，不限往下找几层；leader 不会被这些来回叫醒，读线程时能看到。整件活只由 leader 分配，成员的 @everyone 只到 leader。
- **验证**：成员做完先尽量自己验证，汇报时说清验证了什么、怎么验证的、哪些没验证；leader 不重复成员做过的检查，自己判断要不要再验证：小的自己做，大的再派出去。
- **不抢答、不重复**：bot 发言前检查有没有没看过的新消息，有就先存成草稿、给它看；先发的生效，后发的看到后自己放弃。
- **任务**：认领即锁；状态 To do / In progress / Done / Closed；指派、放下、改派、删除；任务卡片（标题、描述）和完整历史；任务看板；输入框的 As task；bot 自己拆活建任务。
- **线程**：在顶层消息下开线程放支线讨论，只投给关注的人；bot 可以取消关注。
- **@、回复、@everyone、表情回应**；@ 了群外的 bot 或写错名字会被告知；bot 能查自己 @ 的人收到没有。
- **提醒**：bot 给自己定一次性或重复的提醒，到点只叫醒它自己；任务看板下面列出还没响的提醒。
- **附件**：你和 bot 都能在群里发文件；bot 收到别人的附件。
- **bot 问你问题**：问题作为卡片出现在群里，答案回到问的那个 bot。
- **子 agent**：能开子 agent 的 bot 自己在群里协调，大的、能拆开并行的活交给子 agent，小活自己做；有 leader 的群里成员自己做派给它的活。
- **座位换新**：长时间空闲、上下文很大的座位下次被叫醒时换新会话，带一份群里情况的简报。
- **出错恢复**：限流、服务端出错时先等再一起告诉它；同样的错三次就停下；反复失败暂停自动叫醒；你 @ 它马上重新开始。
- **重启后补课**：pocket-bots 重启后，有未读的 bot 收到一批未读消息，读完就停，只处理明确找它的事。
- 回到群时回到上次看到的位置；群内搜索；进入某个 bot 的座位看它的工作过程。

## bot 之间协作（私下）

- `list_bots`、`ask_bot`、`check_chat`：一个 bot 把问题交给另一个 bot（对方开一个新聊天），取回答案；超过约 50 秒的答案在对方答完后自动送回。`ask_bot` 可以让对方的聊天开在发起的聊天的目录里（比如一起看的项目），对方按相对路径读、搜那里的文件；发起者自己的 bot 目录不行。
- 由 bot 的「Contact other bots」设置控制。

## 先设计再写代码（EGM）

按 Google 的 [Elephant-Goldfish Model](https://github.com/google/elephant-goldfish-model)：Elephant 带着你们讨论的全部上下文起草设计文档，Goldfish 只看它被交代的文件，像新人一样挑刺，取舍由你定。

- **两个模板**：Elephant（设计伙伴）和 Goldfish（审阅者），各带一个随 pocket-bots 发布的技能（`egm`、`egm-goldfish`），里面是 EGM 原版的流程、审阅者 persona 和评审标准。
- **用法**：在 Elephant 的聊天里说 `egm brainstorm 想法`、`egm draft`、`egm review 文档路径`、`egm resolve`、`egm drift report 目录`；开场页有这几条示例。
- **金鱼审阅**：Elephant 用 `ask_bot` 给每个审阅者派一个任务，只写 persona、评审标准和文件路径；Goldfish 每个任务开一个新聊天，不带 Recent work，在 Elephant 的项目目录里只读。一个阶段的答案到齐，Elephant 汇总成报告，再和你逐条处理。
- **限制**：Goldfish 的「只读」在 Codex、DeepSeek Harness 上由沙箱保证，在别的 agent 上靠审批和指令；它能不能用 `search_chats`、读 `AGENTS.md`，也只靠指令约束。

## 提议卡片

- bot 不能直接改设置、建技能、建定时任务，只能提议：New skill、New routine、Setup changes。提议只在 bot 自己的聊天里，群聊的座位里没有。
- Setup changes 能建 bot、改 bot 的指令 / 模型 / 审批模式 / 技能 / MCP / 应用 / Playbook、建定时任务、改默认值；卡片逐条列出改动，原样显示要写进 prompt 的文字，扩大权限、删除之类的单独提醒。

## 连接的应用（Composio）

- 用你自己的 Composio 项目连接 Gmail、Slack、GitHub、日历等；同一个应用可以连多个账号并起名。
- 每个 bot 单独打开需要的应用，选工具范围（全部、只读、手动挑）和账号（固定或由 bot 按名字选）。
- key 只存在本机，bot 拿不到；本机 relay 只放行给这个 bot 打开的应用和工具。

## 管理

- 导出（可带记忆）、导入（单个 bot 或多个 bot 的文件）、复制、存为预设、置顶、隐藏（仍然工作）、归档（停止工作，可恢复）、删除。
- 设置 → Back up：所有 bot 打成一个文件。

## 侧栏和搜索

- 侧栏：团队和它的 session（成员头像、leader、状态点）、每个 bot 和它的聊天、置顶、手动排序、折叠、隐藏的 bot、归档的 bot。状态点：在跑、等审批、出错、有新回复；已读状态由 pocket-bots 记，换浏览器也一样。
- **⌘K**：按名字跳到 bot、团队、session、聊天、定时任务；全文搜索所有单聊和 session 的消息（词的一部分、中文都行），选中后打开并定位到那条消息。

## 运行

- 一个 Node 进程，数据都在 `~/.pocket-bots`；`npm run service -- install` 装成登录后自动启动、退出后自动重启的服务（macOS launchd、Linux systemd）。
- 一个数据目录只跑一个实例。
- Web UI 默认只监听本机；按 Host 头防 DNS rebinding；可以在 `config.json` 里放行域名，在可信网络里从别的设备访问。
- 实时更新：断线自动重连并补拉；重启后聊天续接、群聊补课、错过的定时任务和提醒补上。
